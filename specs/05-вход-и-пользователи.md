# Вход по ссылке и многопользовательский режим

## Зачем

До сих пор приложение было записной книжкой одного человека: кто открыл адрес — тот и хозяин всех записей.
Теперь у каждого человека свой аккаунт и своя записная книжка. Вход — без пароля, по ссылке из письма.

## Решения автора (18.09.2026)

1. **Каждый видит только своё.** Свои контакты и заметки; чужой контакт не открывается даже по прямой ссылке.
2. **Войти может любой со своей почтой.** Первый вход сам создаёт аккаунт — с пустым списком. Отдельной
   регистрации нет.
3. **Библиотека входа — Better Auth** (не своя реализация).
4. **Письма — в Mailpit.** Это почтовый ящик на этом компьютере (Docker, рядом с базой): письма никуда
   не уходят, их видно на http://localhost:8025. Настоящая почта — вместе с хостингом.

## Как работает

- Без входа любой адрес приложения ведёт на экран входа `/login`.
- Человек вводит почту → «Получить ссылку для входа» → приходит письмо «Вход в Личную CRM» со ссылкой.
- Ссылка действует **5 минут** и срабатывает **один раз**. Нажал — вошёл, открылся свой список.
- Первый вход с новой почтой создаёт аккаунт; список пустой.
- Вход держится **7 дней** и продлевается, пока приложением пользуются. «Выйти» — в шапке.
- 999 выдуманных контактов из сида принадлежат аккаунту **`demo@example.com`**.
- Почта хранится в нижнем регистре: `Anna@Example.com` и `anna@example.com` — один аккаунт.

## Экран

**Экран входа** — по центру: заголовок «Личная CRM», строка «Вход по ссылке из письма — без пароля»,
поле «Почта» (курсор уже в нём), кнопка «Получить ссылку для входа». Пока запрос идёт — «Отправляю…»,
кнопка заблокирована.

**После отправки** — «Письмо со ссылкой отправлено на anna@example.com. Ссылка действует 5 минут.» и
кнопки «Отправить ещё раз» и «Другая почта».

**Шапка** основного экрана — справа почта вошедшего и кнопка «Выйти».

## Плохой день

- Почта пустая — «Укажи почту»; с опечаткой — «Проверь почту — похоже, в ней опечатка». Введённое не стирается.
- Письмо не ушло (Mailpit не запущен) — «Не удалось отправить письмо» + «Повторить». Почта остаётся в поле.
- Слишком много запросов подряд (больше 5 в минуту) — «Слишком много попыток — подожди минуту».
- Ссылка устарела или уже использована — экран входа с текстом «Ссылка для входа устарела или уже
  использована — получи новую».
- Вход истёк, пока была открыта вкладка — действие не выполняется: «Вход истёк — войди снова». Набранный
  текст остаётся в поле.
- Открыл ссылку на чужой контакт — «Такого контакта больше нет», как для удалённого: что такой контакт
  есть у кого-то другого, не видно.

## Когда… / Тогда…

- Когда человек без входа открывает `/` или `/?contact=412`, тогда он попадает на экран входа.
- Когда человек нажимает ссылку из письма в первые 5 минут, тогда он входит и видит свой список.
- Когда ту же ссылку нажимают второй раз, тогда вход не происходит, и экран входа говорит, что ссылка
  устарела или использована.
- Когда входит новая почта, тогда создаётся аккаунт с пустым списком.
- Когда человек открывает чужой контакт по номеру, тогда видит «Такого контакта больше нет».
- Когда человек пытается добавить заметку, изменить, отметить «Пообщались» или удалить чужой контакт
  (или удалить чужую заметку), тогда ничего не меняется, и он видит «такого больше нет».
- Когда человек нажимает «Выйти», тогда попадает на экран входа, и основной экран снова закрыт.

## Данные

Таблицы Better Auth (устройство задаёт библиотека, имена — во множественном числе, как `contacts`):

| Таблица         | Что хранит                                                                  |
| --------------- | --------------------------------------------------------------------------- |
| `users`         | аккаунт: почта (уникальная), имя (пустое), «почта подтверждена», даты        |
| `sessions`      | вход: токен, до какого времени действует, чей                                 |
| `verifications` | ссылки для входа: **хеш** токена (сам токен в базе не лежит), срок           |
| `accounts`      | способы входа (Google и т. п.); для входа по ссылке не используется          |

В `contacts` — новая обязательная колонка `owner_id` → `users.id`. Удалили аккаунт — удалились его
контакты и заметки. У заметки владельца нет: её владелец — владелец контакта.

Миграция отдаёт уже существующие контакты аккаунту `demo@example.com` (создаёт его, если контакты есть).

## Словарь

| В интерфейсе          | В коде                                                   |
| --------------------- | -------------------------------------------------------- |
| аккаунт, пользователь | `user` / таблица `users`                                  |
| вход (держится 7 дней) | `session` / таблица `sessions`                           |
| ссылка для входа      | magic link; `sendMagicLink`, `signIn.magicLink`           |
| чьи это контакты      | `ownerId` / `owner_id`                                    |
| почтовый ящик для разработки | Mailpit, `CRM_SMTP_URL`                           |

Правила ввода почты — только `features/auth/validation.ts`; письмо — только `features/auth/login-email.ts`;
настройка Better Auth — только `features/auth/data/auth.ts`.

## Настройки

- `CRM_SMTP_URL` — куда отправлять письма; по умолчанию `smtp://localhost:1025` (Mailpit).
- `BETTER_AUTH_URL` — адрес приложения для ссылок в письмах; по умолчанию `http://localhost:3000`.
- `BETTER_AUTH_SECRET` — ключ подписи входа. В `npm run dev` не нужен (Better Auth берёт свой ключ для
  разработки). Для `npm start` и хостинга обязателен — строку в `.env` добавляет автор.

## Не входит

Настоящая отправка писем наружу, вход через Google и passkeys, смена почты, удаление аккаунта, «выйти на
всех устройствах», общие контакты между аккаунтами, возврат на нужный адрес после входа.

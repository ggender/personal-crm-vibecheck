# database-status Specification

## Purpose
Приложение не запускает экран на базе, которая отстала от кода, и внятно говорит, что делать, когда база недоступна. Данные при этом не теряются.

## Requirements

### Requirement: База устарела
Система SHALL перед проверкой сессии на `/` и `/login` выяснять, все ли миграции кода применены к базе. Если нет — вместо страницы показывать «База устарела» с пояснением, что данные на месте, командой `npm run db:migrate` и кнопкой «Проверить снова», которая заново загружает страницу. Сам экран приложения при этом не выполняется. База без единой миграции считается отставшей на все миграции.

#### Scenario: Не хватает миграции
- **WHEN** у базы нет последней миграции кода
- **THEN** на `/` и на `/login` показано «База устарела» и `npm run db:migrate`, ответ страницы не содержит список контактов

#### Scenario: Проверить снова
- **WHEN** миграция применена и нажато «Проверить снова»
- **THEN** показан список контактов, экрана «База устарела» нет

#### Scenario: База никогда не мигрировалась
- **WHEN** в базе нет таблицы миграций
- **THEN** все миграции кода считаются неприменёнными

#### Scenario: Все миграции на месте
- **WHEN** у базы есть каждая миграция кода
- **THEN** проверка отвечает «нет», в лог ничего не пишется; при отставании — строка предупреждения с числом миграций

### Requirement: База недоступна
Система SHALL при недоступной базе не выдавать «База устарела», а дать странице упасть со своей ошибкой: экран «Что-то сломалось» с пояснением, что данные в Postgres на месте, кнопкой «Попробовать снова», подсказкой про Docker Desktop, `docker compose up -d` и `npm run db:reset`, и кодом ошибки.

#### Scenario: Postgres не отвечает при проверке
- **WHEN** запрос о миграциях завершился сбоем, не связанным с отсутствием таблицы
- **THEN** проверка отвечает «нет», и страница показывает свою ошибку

#### Scenario: Экран ошибки
- **WHEN** экран не удалось загрузить
- **THEN** показано «Что-то сломалось» с «Попробовать снова», подсказками и кодом ошибки

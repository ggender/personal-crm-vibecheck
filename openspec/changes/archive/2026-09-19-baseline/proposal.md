# Proposal

## Why

У приложения нет единой спецификации: требования разбросаны по плану сборки и документам отдельных фич, и по ним нельзя проверить покрытие тестами или переформулировать требование, не потеряв связь с кодом. Дальше все изменения идут через OpenSpec, поэтому нужна точка отсчёта — слепок того, что приложение делает сейчас, снятый с кода и тестов на коммите `2e43f14`.

## What Changes

- Код не меняется. Это изменение только для спецификации.
- Появляются девять главных спецификаций — по одной на возможность продукта. Каждое требование описывает наблюдаемое поведение; каждый сценарий — поведение, которое есть в коде. Большинство сценариев уже доказаны тестами; тридцать пока нет, они перечислены в разделе Impact и станут задачами следующего изменения.
- Внутрь спецификации не попадают: сид с 999 контактами, команды обслуживания базы, формат строки лога, раскладка и цвета экрана. Это инструменты разработки и дизайн, а не поведение продукта.
- Принятые допущения при нарезке (легко поменять на ревью через `/opsx:update`):
  - поиск выделен в отдельную возможность `search`, а не растворён в `contacts`;
  - изоляция данных (`ownership`) и то, что не попадает в логи (`privacy`), — две разные возможности;
  - клавиатура и фокус записаны только как сценарии внутри требования, а не отдельными требованиями.

## Capabilities

### New Capabilities

- `contacts`: карточка контакта, форма создания и изменения с проверкой полей, удаление с вопросом, пустые состояния списка и правой панели, состояние экрана в адресе.
- `search`: поиск по имени и порядок списка: регистр, «ё», несколько слов, дефисы, служебные символы, счётчики над списком, «Искать среди всех».
- `notes`: лента заметок контакта, даты «сегодня/вчера», лимит длины, первая заметка вместе с контактом, удаление, судьба заметок при удалении контакта.
- `keep-in-touch`: ритм общения, отсчёт от последнего разговора, список «Пора написать» и отметка «Пообщались» в карточке и в строке списка.
- `groups`: группы контактов: создание, переименование, удаление, ряд групп над списком, фильтр «Без группы», группы в форме и в карточке.
- `auth`: вход по ссылке из письма, письмо, повторное использование ссылки, выход, проверка адреса, ответы на ошибки отправки.
- `ownership`: у каждого пользователя свои данные: чужой контакт, группа и заметка выглядят как несуществующие; истёкшая сессия отвергает действие без потери введённого.
- `privacy`: что не попадает в логи и в тексты ошибок: имена, телефоны, почта, тексты заметок, названия групп, токен сессии, ссылка для входа.
- `database-status`: экран «База устарела» до сессии на обеих страницах, «Проверить снова», экран «Что-то сломалось» при недоступной базе.

### Modified Capabilities

Нет: существующих спецификаций ещё не было.

## Impact

- Код, тесты, схема базы и зависимости не затронуты. Проверка: `git diff --stat -- src e2e` пустой после архивации.
- После `/opsx:archive` в `openspec/specs/` появятся девять главных спецификаций — единый источник правды для следующих изменений.
- Документы `specs/00`–`06` остаются как история; новые документы такого вида больше не пишутся.
- Сценарии без теста на момент слепка — вход для изменения `cover-baseline-scenarios`:
  - `contacts`: Курсор в поле имени · Enter в текстовом поле сохраняет · Отмена без изменений · Приложение не отвечает (форма контакта) · Пустые поля и ссылки · Выбранный контакт отмечен в списке · Переход к карточке с клавиатуры · Подсказка на старте · Список пуст
  - `search`: Пауза после ввода · Enter отправляет сразу
  - `notes`: Счётчик знаков · Лента пуста · Окно подтверждения
  - `keep-in-touch`: Никому не пора
  - `groups`: Escape отменяет переименование · Групп нет · Ряд без групп · Все по группам
  - `auth`: Вошедший на странице входа · Отправить ещё раз и другая почта · Слишком много попыток · Письмо не ушло · Приложение не отвечает (форма входа) · Другая ошибка ссылки
  - `ownership`: Текст остаётся на экране
  - `privacy`: Сбой загрузки экрана · Токен ссылки · Сообщения библиотеки входа
  - `database-status`: Экран ошибки

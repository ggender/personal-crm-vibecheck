# Design

## Context

Мотивация — в proposal.md. Условия, в которых живут тесты:

- e2e идут на production-сборке на порту 3100 со своей базой `crm_e2e` и Mailpit; один воркер, общая база, демо-сессия входит один раз в `auth.setup.ts`.
- Better Auth в production-сборке выдаёт не больше пяти ссылок для входа в минуту с одного адреса.
- Сбой «приложение не отвечает» в существующих сценариях воспроизводится обрывом запросов Server Functions через `page.route` (`dropServerFunctions`).
- «База устарела» проверяется прямой правкой таблицы миграций в `crm_e2e` с восстановлением в `finally`.
- Юнит-тесты — Vitest, `LOG_LEVEL=silent`; тесты, которым нужен лог, ставят `LOG_LEVEL=debug` и перехватывают `console.error`.

## Goals / Non-Goals

**Goals:**
- Каждый из 30 сценариев получает тест на том уровне, где поведение наблюдаемо: в браузере — Playwright, в коде — Vitest.
- Тесты не зависят от порядка и не оставляют следов в базе, кроме созданных ими контактов и аккаунтов, как и существующие.

**Non-Goals:**
- Новый слой тестов компонентов (jsdom, testing-library) не вводится.
- Существующие тесты не переписываются.

## Decisions

- **Сценарии нового аккаунта — в одном файле с одним входом.** `e2e/zero-contacts.spec.ts` объявлен `serial`, входит один раз и держит страницу между тестами. Так пустые состояния (список, ряд групп, панель, «Без группы», «Пора написать») стоят одной ссылки для входа. Имя файла сортируется после `scenarios.spec.ts`, чтобы ссылки нового файла не попали в ту же минуту, что ссылки `auth.spec.ts` и `auth.setup.ts`. Альтернатива — отдельный вход на тест — упирается в лимит пяти ссылок.
- **Ошибки формы входа подменяются на сети.** 429 и отказ почты — `route.fulfill` с нужным статусом на `**/api/auth/sign-in/magic-link`, молчание приложения — `route.abort`. Настоящих ссылок эти тесты не тратят. Альтернатива — реально упереться в лимит — сломала бы остальные сценарии.
- **«Отправить ещё раз» и хеш токена — в цепочке входа нового аккаунта.** Первая ссылка запрошена формой, вторая — кнопкой «Отправить ещё раз»; по второй входим. Между ними читаем свежую строку `verifications`: ни одна колонка не содержит токен из ссылки. Итого две настоящие ссылки на весь файл.
- **Сломанная база — переименованием таблицы.** Тест переименовывает `contacts` в `crm_e2e`, открывает `/?q=<слово>`, ждёт «Что-то сломалось», проверяет, что слова нет в видимом тексте, возвращает таблицу в `finally`, нажимает «Попробовать снова» и видит список. Проверка «База устарела» проходит (таблица миграций цела), сессия проходит, падает загрузка экрана — ровно тот путь, что описан в спеке. Альтернатива — остановить Postgres — недоступна из теста.
- **Пауза поиска и Enter — через `page.clock`.** Часы страницы замораживаются до перехода; три буквы с `runFor(100)` между ними не дают запроса, `runFor(250)` даёт один; Enter при замороженных часах даёт запрос сразу. Если часы окажутся несовместимы с гидрацией, запасной вариант — считать RSC-запросы без заголовка `Next-Router-Prefetch`: одна серия букв даёт один запрос с полным словом.
- **Сообщения библиотеки входа — юнит-тест на настроенном логгере.** `getAuth()` собирает Better Auth лениво и без обращения к базе; тест вызывает `options.logger.log` с текстом, содержащим адрес, и проверяет строку `better_auth.<level>` без этого текста. Альтернатива — e2e через настоящую ошибку Better Auth — не воспроизводится надёжно.
- **Исключение из «сначала красный».** Тесты фиксируют существующее поведение, поэтому проходят с первого запуска. Вместо красного прогона — сверка каждого теста со сценарием спеки по названию и шагам; это записано в tasks.md как проверка.

## Risks / Trade-offs

- [Замороженные часы ломают гидрацию или переходы Next.js] → запасной способ по счёту запросов, описан выше.
- [Переименованная таблица остаётся после упавшего теста] → восстановление в `finally`; `npm run db:reset` перед каждым прогоном e2e всё равно собирает базу заново.
- [Пять ссылок в минуту] → новых настоящих ссылок две, файл идёт последним; ошибки входа — подменой на сети.
- [Прокрутка к выбранному зависит от высоты окна] → проверяется `toBeInViewport` на контакте из конца списка, а не координатами.

# Личная CRM

Записная книжка о людях, которых знаешь лично: кто это, откуда знакомы, телефон и почта — и лента заметок
«о чём договорились». Работает только на твоём компьютере.

## Запуск

Нужны:

- Node.js 22 или новее (проверить: `node -v`). На более старой версии `npm install` откажется ставить
  зависимости и напишет «Unsupported engine».
- Docker Desktop: в нём работает база данных Postgres. Перед работой открой Docker Desktop и дождись,
  пока он запустится.

```bash
npm install              # один раз: поставить зависимости
docker compose up -d     # запустить базу (после перезагрузки компьютера — снова)
npm run db:reset         # один раз: создать базу и наполнить её 999 выдуманными контактами
npm run dev              # запустить приложение
```

Открой [http://localhost:3000](http://localhost:3000). Остановить приложение — `Ctrl+C` в терминале.
Остановить базу — `docker compose stop` (данные сохранятся).

## База данных

- Данные хранит **Postgres 17** в Docker: база `crm` на порту 5433. Порт открыт только для этого
  компьютера, пароля нет.
- Сами данные лежат в томе Docker `crm-postgres`, не в папке проекта, — в Git они не попадут.
- `npm run db:migrate` — создать базу, если её нет, и обновить её устройство после изменений в коде.
- `npm run db:seed` — наполнить пустую базу 999 выдуманными контактами. Если контакты уже есть, ничего не делает.
- `npm run db:reset` — **удалить базу целиком** и собрать заново с 999 выдуманными контактами.
  Всё, что ты вносил руками, пропадёт. Приложение можно не останавливать: оно само переподключится.
- **`docker compose down -v` удаляет все данные** (ключ `-v` стирает том). Чтобы просто остановить базу,
  используй `docker compose stop`.
- Другая база — через переменную `CRM_DATABASE_URL` (так работают сценарии `npm run test:e2e`: база `crm_e2e`).

## Резервная копия

Копия — это один файл `.sql` с выгрузкой всей базы. Команды выполняй в папке проекта, база должна быть запущена.

1. Сделать копию:
   `docker compose exec -T db pg_dump -U postgres --clean --if-exists crm > ~/Documents/crm-backup-$(date +%F).sql`
2. Восстановить из копии (всё, что появилось в базе после копии, пропадёт):
   `docker compose exec -T db psql -U postgres -d crm -v ON_ERROR_STOP=1 < ~/Documents/crm-backup-2026-09-18.sql`
   — подставь имя своего файла. Если базы нет совсем (например, после `docker compose down -v`), сначала
   `docker compose up -d` и `npm run db:migrate`, потом команда восстановления.

## Если что-то пошло не так

- **«Что-то сломалось»** на весь экран — приложение не смогло открыть базу. Чаще всего не запущен Docker
  Desktop или база: запусти Docker Desktop, выполни `docker compose up -d` и нажми «Попробовать снова».
  Если не помогает — посмотри в терминал, там будет строка со словом `ERROR`. Если базы ещё нет, собери
  её: `npm run db:reset`.
- **«Postgres не отвечает»** при `npm run db:*` — то же самое: запусти Docker Desktop и `docker compose up -d`.
- **«Не удалось сохранить»** под заметкой — приложение не ответило. Текст остаётся в поле: проверь, что в
  терминале запущен `npm run dev`, и нажми «Повторить».
- **Изменения не видны в другой вкладке** — так и задумано в V1: обнови страницу (F5), и они появятся.

## Что важно помнить

- Входа по паролю нет: V1 рассчитан только на твой компьютер. Не открывай приложение в интернет и не вноси
  настоящих людей в базу, доступную другим, пока не появится вход (план V2).
- Журнал событий пишется в терминал, где запущен `npm run dev`. В нём только номера и длины — ни имён,
  ни телефонов, ни текстов заметок. Подробнее: `docs/DEBUG-LOGGING.md`.
- План сборки: `specs/02-план-сборки.md`, эскизы: `specs/boards/`.
